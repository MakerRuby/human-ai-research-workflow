# 人与 AI 科研协作工作流

**Human–AI Research Workflow** · `human-ai-research-workflow` · v4.0.0

这是人与 AI 合作完成生物医学科研的全流程工作流。负责人只需提出一个初步想法，AI 就会引导把问题具体化，评估现状与科学增量，组织多个假设竞争，再陪同完成设计、执行、解释和论证骨架，一直到投稿前材料。在关键节点，AI 给出推荐和理由，由负责人拍板。工作流适用于公开数据、组学、湿实验、动物、临床和系统评价研究，并按任务调用已可用的专项技能。

它由普通文件和可选辅助脚本组成，核心规则不依赖某一 AI 产品。科研判断、真实授权和专业审阅仍由项目责任人负责。

## 能做什么

- 用启动问卷、澄清度阶梯和追问清单，把模糊想法推到可回答、可证伪的问题；产出证据地图、科学增量评估和答案矩阵。
- 借鉴 Google AI co-scientist：多策略生成假设，分层评审，两两比较并用 Elo 排序，进化与元评审；负责人的假设同等参赛，人评的一致率单独报告。
- 借鉴 Stanford Biomni：数据库、工具、技能与操作经验（know-how）的注册表，两段式检索，以及附运行编号的计划清单。
- 每个研究任务都挂到问题树上，配意图简报和解释简报，让人始终知道这一步为什么做、能说明什么。
- 从第一天起维护论证骨架和图故事板，结果验收后立即写进章节草稿；检索日志避免重复检索。
- 按研究类型裁剪流程：湿实验在环、伦理关口与注册关口、对应的报告规范。
- 在完整投入前先核实科学问题、数据与方法的可行性。
- 按交付物、验收依据、风险和依赖拆分近期工作。
- 统一目录职责，记录发现、决策、版本与开放变更。
- 持续积累有价值来源，以来源索引、核心证据卡和稳定编号连接研究与写作。
- 按影响决定何时请负责人拍板，按独立性与协调成本决定是否并行。
- 本地能力不足时再审慎评估外部开源工具，并核对许可证、依赖与数据边界。
- 追踪修改对结果、图表、正文、复现和审阅的影响。
- 生成离线只读审阅页，让负责人查看问题、备选与证据。
- 保存实际运行日志与快照，比较新输出，明确复现范围。
- 固定一轮投稿材料，保留退出使用的成果及其理由。

## 开始使用

支持技能机制的助手：按所在工具的说明加载完整目录。其他助手：要求它先读取 [SKILL.md](SKILL.md)，再读取本轮需要的参考文件。

可直接使用这段指令：

> 请按 human-ai-research-workflow 的 SKILL.md 协助管理当前研究。先读取现有项目入口、方案和状态，沿用已有目录；核对开放变更和证据，按需调用实际可用的专项技能，继续已授权的下一项工作。

辅助脚本需要 Python 3.9+，仅使用标准库；研究分析程序继续使用自己的环境。先预览初始化，不覆盖旧项目：

```sh
python scripts/init_project.py --target "你的项目目录" --name "研究名称" --scale L --profile research --dry-run
```

确认路径和初始化范围后，移除 `--dry-run` 执行。完整说明见 [USAGE.md](USAGE.md)。没有终端权限时，可由有权限的人执行，并回传真实输出。

## 验证与边界

```sh
python -B -m unittest discover -s scripts -p "test_*.py" -v
```

Windows 下已进行行为测试；具体结果见发布说明。检查器只核查已登记的关系和证据，不能证明科学结论真实，也不能自动发现正文的全部语义影响。离线页面是快照，不会写入负责人批准。项目采用单一状态写入者；脚本不提供任意代码沙箱。

## 版本与许可

技能名称保持稳定，版本保存在元数据和 Git 标签中。由 `ai-project-blueprint-v3` 更名而来，参见 [迁移说明](references/migration.md)。

当前尚未选择开源许可证。公开发布与许可授权是不同决定；在作者选择并加入 LICENSE 前，本仓库不声明采用某种开源许可证。

科研项目初始化会创建来源索引和空白核心来源卡模板；一般项目和简单一次性任务不会额外建立资料库。希望新会话持续沿用工作流时，初始化默认生成 `AGENTS.md` / `CLAUDE.md`，统一引导读取 `AI_CONTRACT.md`；参数、已有入口合并和加载验证见 [USAGE.md](USAGE.md)。

首次启用口令：**初始化本项目并启用持续协作。** 本技能用于项目实施时也会自动检查绑定；已有项目沿用原记录，仅补必要入口。
