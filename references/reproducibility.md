# 可复现性管理

## 状态的含义

| 状态/范围 | 可以说明 | 不能自动说明 |
|---|---|---|
| 材料记录齐全 | 有输入、代码、参数、环境与运行说明 | 已实际执行 |
| smoke | 小规模流程实际跑通 | 全数据结果一致 |
| partial | 声明的部分分析已重跑并比较 | 所有关键结论被覆盖 |
| full | 声明的完整分析范围已执行并逐项比较 | 独立团队复现或科学结论正确 |
| 独立复现 | 另有独立执行者、环境和范围的证据 | 仅换一个 AI 评语即可实现 |

所有范围都由项目定义并专业审阅；代码不能自动推断“全部关键分析”。真实环境重建与仅记录环境版本分开，种子不保证跨硬件/算法逐字节一致。

full同时写清从哪些实际输入开始、到哪些输出结束及未覆盖步骤。冻结分析输入后的全拟合，不自动覆盖原始获取、清洗/注释或新环境；计算重复也不等于新研究单位确认。

## 实际运行

复制 `assets/run-spec.json` 到项目管理目录并填实际值：`id`、`purpose`、`inputs`（成果编号+版本）、`code` 文件列表、`config`、`environment` 文件、`environment_rebuilt` 布尔值、`cache_policy`、全新的 `outputs` 路径。环境文件应记录实际解释器、依赖锁定、系统/硬件等与项目相关条件；布尔值本身不能证明重建。

```text
python <skill>/scripts/run_project.py --project <project> --spec _pm/run-spec.json --timeout 600 -- <实际解释器> <实际脚本> <参数>
```

只执行这次明确提供的 argv，不执行历史 JSON 内的命令。程序保存代码/参数/环境文件快照、输入哈希、开始结束时间、标准输出错误、退出码和新输出哈希。输入数据可较大，不自动复制全部数据，应另有不可变存储或下载恢复路径。实际运行的直接工作目录是项目根。脚本不隔离任意代码，也不保证结束所有衍生子进程。

失败、超时、缺输出或输入被改动都保留证据，不能计为成功。外部强杀/断电可能留下 running；续接时先核对真实进程和输出，记录恢复判断，保留原证据后用新编号重跑，不将其手工改为成功。

运行配置与持续更新的项目授权/状态分开；执行中不修改已快照的代码、输入或参数。只修缓存、读取次数或时间上限也用新运行并说明科学参数是否改变，不把性能修复写成方法变更或全流程效率提升。

仅查元数据的运行可在规格中显式写 `stage: "metadata"`，含义是未读取目标读出/效应，用于避免单凭取文件就误触发 CP3；`analysis` 和 `validation` 用于相应运行。未填的历史运行按未知阶段保守提示，不按 purpose 文本猜测。阶段标签不是盲法证明，接触记录和实际代码仍需核对；其他已选假设或 G2/G3 状态照常触发 CP3 检查。

规格含 `task` 且任务已有意图时，运行器在任何运行写入/命令执行前核对简报，自动在 run.json 写 `intent_ref`（path/written_at/sha256）并保留 `intent` 快照。未来更新意图不改变旧绑定。可在规格提供同值的 `intent_ref` 作一致性断言，不能用它选择已被替代的意图。旧无此字段的运行按登记历史只读核查；历史缺口不会因此变成已通过。

## 模拟与复杂筛选：可运行和有信息分开

当论文依赖模拟来解释程序行为，尤其有联合检验、选择或多重负担时，冻结正式网格前先作小型先导：阴性、可检出的阳性及关键边界/过渡是否覆盖；报告选择这些情景的依据和假设。已有公式/边界夹具验证计算，不等于场景能分辨答案；强阳性下检出也不等于现实研究功效或FDR已校准。

先导用于决定网格是否回答目标问题，不用于优化出想要的结论。若所有真值场景都无检出，先检查实现及设计的信息性，不直接判程序错误或生物现象不存在。保留已经冻结/已见的网格与结果；新增情景另版标明接触后提出和理由，不覆盖原网格、不挑选最有利情景。不可行或合理的退化边界也可以报告，明确它没有回答什么。不要求每个描述分析、画图或数据整理都另做功效模拟。

## 实际比较

```json
{
  "id":"REP-001","title":"主要结果重跑","run":"RUN-001",
  "scope":"full","required":true,
  "inputs":[{"id":"DATA-001","version":"v1"},{"id":"RESULT-001","version":"v1"}],
  "by":"实际执行者及角色","rationale":"按方案逐项比较",
  "comparisons":[{"expected":"results/main.json","actual":"runs/output-001/result.json","mode":"json_numeric","atol":0,"rtol":0}],
  "limitations":"零容差只是示例；完整范围需按实际分析说明"
}
```

保存为项目相对路径后运行 `verify_reproduction.py --project <project> --spec <spec>`。预期结果必须是登记的版本化输入；实际文件必须是本次成功运行的新输出，不能用同一个文件自比。报告保留通过/失败、各项哈希与容差；旧报告不覆盖。

内置比较仅支持 sha256 和 JSON 数值结构比较。后者使用 `abs(actual-expected) <= atol + rtol*abs(expected)`，要求显式有限非负容差，拒绝非有限数，布尔值不视为数字。CSV、图像、统计模型、文档等使用适用专项工具生成额外检查证据；不能用未覆盖的内置比较冒充完整验证。

多文件或嵌套路径用明确文件清单：实际文件须属于真实新运行的outputs，预期文件须有登记来源，逐项比较并说明覆盖；不要以目录存在、自动通配扫描或一份汇总自比代替完整范围证据。当前工具不自动推断嵌套管线或科学覆盖。

核查器会识别结果版本、当前代码/参数/环境与报告引用的偏离；远程数据库发生变化但本地清单未变时，不会自动发现。正式方案、原始数据许可与恢复、样本排除、人工修改、随机性、探索接触均需在科研记录中说明。

## 预检与正式执行同源

执行前的预检（身份映射、覆盖、样本分组、可检测性过滤）要产出一个冻结的输入对象，例如 `.rds`、`.parquet` 或 `.h5ad`，并登记散列。正式脚本只能加载这个对象，不得重新实现同一套映射或过滤逻辑。原因是：两份代码各写一套，即便都“看起来正确”，结果也可能不一致，预检通过就失去意义。

- 预检中被检查的数值（例如共同覆盖的基因数），要在正式脚本中用断言重复检查；不一致时停止运行，不能降低标准继续。
- 声称仅身份元数据预检时，不读取目标效应；设计先导/预实验若需要目标读出，按实际接触登记，不靠“预检”名称宣称未泄漏。执行对象的散列写入运行记录。
- 修改映射规则后，重新生成预检对象并另建运行，不覆盖失败的运行；写出完整变更影响，包括基因宇宙的变化，而不只是触发问题的那几个基因。

## 先验收再报告

后台任务退出码为 0，只说明程序跑完了。面向负责人的数字、样本数和结论，只能来自经过验收的输出：核对行列数、身份、分组、区间和关键计算。初步诊断要标注“初步”，确认后再下结论；发现先前报告有误时，用一句话说明更正，不能沿用。

AI 生成且进入正式研究的材料须冻结为实际文件，登记模型/工具可得标识、时间、输入输出版本、用途与人工核查证据。保存可审计摘要和产物，不要求模型内部思维过程，也不承诺模型服务未来输出确定。
