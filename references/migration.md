# 既有项目适配与状态兼容

先读原入口、方案、状态和成果，确认权威记录及冲突。缺一个文件不等于新项目；不因采用技能重建研究或补造历史批准。规则职责见[目录](project-layout.md)，启用方式见[使用](../USAGE.md)。

## 最小适配

1. 保留原目录、编号和配置；已有JSON/YAML等价记录先复用，不建立第二套事实源。
2. 用`init_project.py --dry-run`核补缺清单；已有业务目录可加`--no-research-folders`，跳过默认目录README占位。此选项不自动推断目录/合并文档/修改已有state。
3. 实际职责映射在既有layout与LAYOUT审阅后维护，原始材料不移动；AI_CONTRACT及宿主导航按原授权最小合并，脚本跳过不等于合并完成。
4. 从当前阶段的下一交付物登记必要证据。旧PASS不自动等于当前accepted或完整复现；恢复不了的历史标缺失，不倒推接触前方案。
5. 实质适配前保留受影响原件/指纹，适配后核未意外丢失及实际依赖，不为统一格式重写稳定文件。

## 状态与版本

- 新项目采用schema2，字段及旧v1基础兼容见[状态结构](state-schema-v2.md)。检查器可读v1，不表示v2扩展治理已通过；采用要求v2的工具前须显式审阅迁移，保留原ID/路径及已有证据。
- v4沿用schema2，可选questions/hypotheses及后续字段按实际需要补，不追补虚构历史。新任务挂靠问题，已做检索能恢复则记，不能恢复则说明。
- 新控制状态、检查/验收和意图绑定按[治理](governance.md)、[复现](reproducibility.md)使用；旧项目自定义字段先核原语义，不自动改造。
- 迁移改变的是记录表示，不能自动重新批准研究、恢复停止任务或放行验证效应。

旧名ai-project-blueprint-v2/v3及历史规则修订见[更新日志](../CHANGELOG.md)。技能改名或升级不要求搬研究文件；源副本、安装和发布分别核实，维护本地副本不自动更新其他位置。
