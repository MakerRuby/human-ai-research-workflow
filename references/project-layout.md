# 目录与唯一事实源

先检查现有项目。默认布局是可调整的职责建议；初始仅创建管理文件，业务文件夹在第一次有实际内容时建立。`_pm/LAYOUT.md` 是唯一的人类可读文档职责登记表，根 `README.md` 提供导航和当前交付包索引；`project-state.json` 仅维护机器状态、版本、依赖和路径映射，不复制完整文档目录。

每份新建的项目文档在开篇用简短字段说明：作用、不负责什么、读者、更新触发条件、与相邻文档的关系。该说明不重复文档正文。更新既有项目时，在本轮新增文档或实质调整职责时补齐；不为补字段而机械重写大量稳定旧文档。新增文档前先查 `_pm/LAYOUT.md` 是否已有同职能入口；有则并入原文档，确需拆分时同步更新登记表。一次性临时输出、机器生成物和数据文件不按文档模板要求添加说明。

| 内容 | 唯一权威位置 | 其他位置可以怎样引用 |
|---|---|---|
| 目标、范围、完成定义 | `_pm/BRIEF.md` 或既有需求文档 | STATUS 简短引用 |
| 权限与执行约定 | `AI_CONTRACT.md` | 任务包引用适用条款 |
| 当前版本、状态、依赖、记录索引 | `_pm/project-state.json` | 页面自动投影，WBS 可解释分工但不另列手工状态 |
| 当前工作上下文与下一动作 | `_pm/STATUS.md` | 不复制完整台账 |
| 研究方案与方法 | `_pm/research/RESEARCH_PLAN.md` | 论文引用方案版本 |
| 数据来源、许可、下载与样本单位 | `_pm/research/DATA_REGISTER.md` | 输入清单引用登记条目 |
| 发现的详细论据 | `_pm/FINDINGS.md` 或按编号分文件 | state 仅保存检索摘要和引用 |
| 决策备选、理由、授权来源 | `_pm/DECISIONS.md` 或按编号分文件 | state 保存索引、状态与责任 |
| 实际运行过程 | `runs/<RUN-ID>/run.json`、快照与日志 | state 只索引运行编号/状态/路径 |
| 测量比较结果 | 运行目录中的 comparison 报告 | state 索引范围与结果 |
| 一轮固定交付的内容和来源 | `releases/<ID>/manifest.json` | 根 README 链接该历史快照 |
| 来源、状态、证据位置与写作用途 | `references/INDEX.md`（科研项目适用） | 核心来源卡与其他记录用 ID 互相引用 |

允许索引、简短摘要、自动生成视图及注明日期的历史快照；禁止几个文档分别手工维护同一整套当前事实。state 的发现摘要便于检索，详细科学解释留在记录中；如果发生冲突，应阻止使用并对齐来源。

默认业务目录：`references/` 来源材料；`data/raw/` 原始输入；`data/interim/` 中间数据；`data/processed/` 可分析数据；`src/` 正式代码；`notebooks/` 探索；`runs/` 实际执行；`results/` 已登记成果；`manuscript/` 正文；`releases/` 固定交付；`review/` 可重新生成的审阅界面。

避免以“最终版/最终最终版”或文件移动表达状态。使用稳定成果编号和显式版本，登记输入版本。只在复杂子目录需要补充来源、生成方式或特殊职责时添加 README；不得让每个 README 变成第二个任务台账。较大二进制数据可登记外部存储清单与校验信息，不能假装清单哈希等于远端数据已重新核验。

明确不再采用的材料使用 `archive/`，退出索引由成果 lifecycle/retirement 负责，目录内 manifest 保存历史内容。参见 [归档规则](archive.md)。保留原件以免证据断链；生命周期改变不要求自动移动当前文件。`references/INDEX.md` 是来源索引，不是文档职责登记表；不在 README、LAYOUT 和机器状态中重复维护完整来源信息。
