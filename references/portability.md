# 宿主适配

核心协议与宿主分离。执行者先确认实际能力，再选择下列方式：

| 能力 | 可用时 | 不可用时 |
|---|---|---|
| 读取项目文件 | 读入口及当前任务相关记录 | 请求必要文本，明确上下文不完整 |
| 发现专项技能 | 使用实际目录、文件或发现机制 | 使用现有可验证工具；关键能力缺失则说明影响 |
| 运行程序 | 本次明确提供 argv，执行并收集实际日志 | 提供具体命令，由人执行，未回传结果前保持待执行 |
| 展示网页 | 浏览器打开生成的本地审阅页 | 阅读 Markdown 和状态表，保持同样决策内容 |
| 登记决定 | 按本次对话或已授权正式渠道的真实答复登记 | 保存待决项，不补写同意 |
| 多执行者协作 | 明确任务接口、权限和合并责任 | 当前执行者依序完成；技能调用不自动授权子代理 |

不要求产品专用工具名称、聊天编号、连接器或自动调度。需要工具专属操作时放在项目适配说明，不将其写为通用必需步骤。

## 常见环境陷阱（Windows 试点中实际遇到）

- **编码**：中文 Windows 默认使用 GBK。读写文本时显式指定 `encoding='utf-8'`（读取 gzip 也一样），控制台输出设置 `PYTHONIOENCODING=utf-8`。不要把解码失败误判为数据损坏。
- **R**：`Rscript` 可能不在 PATH 中，先查找绝对路径（例如 `C:/Program Files/R/R-x.y.z/bin/Rscript.exe`）。不要把多行 R 代码通过 `-e` 传入，引号在 shell 中容易失效；应写成 `.R` 脚本文件再运行。
- **路径**：Git Bash 的 `/tmp` 路径传给 Windows 原生 Python 时可能失效，应使用 `cygpath -m` 或项目内路径。写入前核对盘符和项目根目录，不要把项目文件写到技能仓库或其他盘。
- **GEO series matrix**：表头前可能有空行。应按 `!series_matrix_table_begin` 和 `!series_matrix_table_end` 截取表格，不能简单跳过以 `!` 开头的行。
- **10x CSV 计数表**：表头常常缺少基因列的列名，因此数据行比表头多一列。应使用 `index_col=0` 读取，并抽查若干计数，确认条码与基因没有错位。

## 状态文件

状态文件位置固定为 `_pm/project-state.json`。登记决定、成果与发现时，优先使用 `scripts/record.py`：它先在副本上运行检查器，不引入新错误才写入。不要用临时脚本直接改写 JSON。其中 `layout` 可映射业务目录（数据、代码、运行、成果、正文、交付、审阅等），不改变状态文件本身的位置。对于权威状态已在其他系统维护的旧项目，先决定复用或显式迁移；不要建立两个完整的手工状态库。

同一状态文件采用单写入者；专项技能返回成果与证据，由统筹执行者核对后合并。原子替换避免写出半个 JSON，不提供多人并发事务或分布式锁。
