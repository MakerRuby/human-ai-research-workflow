# 生物医学能力注册表与操作经验

> 作用：说明执行时如何按任务检索数据库、工具、技能和操作经验（know-how），以及如何把执行过程变成可审计的计划清单与运行记录。不负责：运行留痕与复现（见 [复现](reproducibility.md)）、专项技能的调用协议（见 [技能协作](skill-composition.md)）。设计借鉴 Stanford Biomni 的做法后重写，未复制其代码，来源见 [外部经验](design-lessons.md)。

## 1. 为什么需要它

AI 执行生物医学分析时，常见问题不在于不会写代码，而在于：选错数据库或版本，忘了领域里的常见坑（如批次效应、双细胞、多重比较），以及每次重新摸索同一套流程。Biomni 的经验是：先从真实文献的方法部分整理出“行动空间”，每个资源都有结构化描述并经过测试；执行前先按任务检索出相关资源，再加载全文；操作经验写成固定格式的文档。

## 2. 注册表

技能自带的种子注册表在 `assets/capabilities/registry.json`，项目可以在 `_pm/capabilities.json` 中追加或覆盖（项目条目优先）。每个条目包括：

| 字段 | 含义 |
|---|---|
| `id` | 稳定编号，如 `db.geo`、`tool.deseq2`、`skill.pathway-enrichment`、`kh.scrna-annotation` |
| `kind` | `database` / `tool` / `skill` / `know_how` |
| `summary` | 一句话用途，是检索的主要依据 |
| `tags` | 任务关键词（中英文均可） |
| `access` | 访问方式：API、下载、本地技能、需申请 |
| `license` | 许可证或使用条款摘要；`noncommercial` 等限制要写明 |
| `status` | `candidate`（候选）/ `verified`（已冒烟测试）/ `deprecated`（弃用） |
| `verified_at` / `evidence` | 冒烟测试的日期与记录位置（`verified` 必填） |
| `pitfalls` | 最常见的 1–3 个坑 |
| `doc` | know-how 文档路径（若有） |

种子条目只表示“值得考虑”，不保证在当前环境可用。技能类条目使用前，要用宿主的技能清单确认确实已安装；数据库类条目，要在本次运行中实际访问一次，并记下版本和访问日期。

## 3. 两段式检索

```text
python <skill>/scripts/registry_search.py --project <project> --query "单细胞 注释 marker" --limit 8
```

第一段，脚本按 `summary` 和 `tags` 对关键词打分，返回一份短名单（只含 id、类型、摘要、状态和坑）。第二段，AI 从短名单中选定资源，再读取相应的 know-how 文档和技能说明。选择理由写进意图简报；影响主要方法的选择，按决策规则登记 `D-*`。短名单设上限，避免“宁多勿漏”把上下文撑满。

## 4. 操作经验文档

模板在 `assets/capabilities/know-how/TEMPLATE.md`，开头是元数据（简述、作者或来源、版本、日期、许可、适用范围），正文固定几节：

1. 推荐流程（按步骤，标出关键参数）
2. 该做与不该做
3. 常见坑与对策
4. 工具选择表（什么情况用什么）
5. 验证清单（怎样知道结果可信）
6. 排错

经验来自两个渠道：领域公认的最佳实践（附来源），以及本项目的实际教训（附 `F-*` 或 `RUN-*`）。项目里踩过的坑，要在当轮写进项目级 know-how，以免下个会话再犯。

## 5. 计划清单与运行包装

非平凡的分析任务，先在任务目录写一份编号计划清单：

```text
1. [x] 读取 GSE… 并核对样本表 — RUN-003
2. [✗] 用默认参数做批次校正 — 失败：批次与分组完全混杂（F-004）
3. [ ] 改为分层分析并在讨论中说明（D-006）
```

规则：打勾的项目必须附 `RUN-*` 或产物路径；失败的项目保留不删，写明原因，再插入修正步骤。所有命令通过 `run_project.py` 执行（见 [复现](reproducibility.md)），设超时；完整日志落盘，回传给 AI 的只是开头、结尾和报错行。

## 6. 维护规则

- 新资源先登记为 `candidate`。至少完成一次真实的小规模调用、留下记录后，才能标为 `verified`。
- 数据库版本或接口变化时，记录在条目里；依赖它的结果按 [变更](governance.md) 规则追踪影响。
- 许可证必填。投稿包或代码发布时，列出所用组件的许可证；仅限非商用的资源要标注清楚。
- 外部 AI 代理系统（如本地安装的 Biomni）可以作为 `tool` 类条目登记，但默认关闭。启用前要说明以下事项，并取得负责人授权：环境体积、所需 API key、哪些内容会发给哪个 LLM 服务商、是否有沙箱。它的产出同样要按本项目的运行与证据规则入账。
