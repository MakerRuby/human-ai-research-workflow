# 公开数据与代码研究：从问题到投稿前材料

v3 配套协议：[发现与变更](governance.md)、[实际运行与复现](reproducibility.md)、[负责人审阅](reviewer.md)、[固定投稿材料](release.md)、[不再采用材料的归档](archive.md)。从立项开始维护可恢复的数据来源与分析接触记录；每个阶段只要求适用证据，不因普通项目启用统筹技能就强加科研关口。

本流程面向二次数据研究，按设计调整。关口是投资与证据的检查点，不能替代具体领域方法。三类研究不要混淆：描述/关联、预测、因果解释。方法适用性由研究目标、抽样与测量过程决定，不由某种算法的流行程度决定。

## G1：研究问题与立项

输入：已有想法、关键文献、目标人群/系统与资源限制。先形成可被反驳的问题，写清研究单位、比较、结局或目标量、时间关系、预期用途和可支持的结论强度。

产物：问题卡、最接近工作的证据表、候选数据清单、关键反对意见、最小可行性计划。使用 `assets/research/RESEARCH_PLAN.md` 的前半部分；研究来源按 [资料、证据与写作素材](evidence-and-materials.md) 进入候选或保留索引。

检查：

- 已读到支持关键判断的原始来源，区分确证来源、候选线索与无法访问内容；检索范围和截止日期可追踪。未检索不能写“首次”。
- 新增价值具体落在问题、数据覆盖、识别/验证设计或有用的复现检验；不能仅以换算法、换疾病名或多画图论证价值。
- 至少说明一种可能推翻当前解释的竞争假设，以及数据能否检验它。
- 结论目标与数据能力初步相容，下一轮数据探针有投入上限与退出条件。

决策：继续核实数据、缩小问题、补检索或停止。G1 通过不等于已证明创新性，也不允许直接宣告数据可行。

## G2：实际数据可行性

输入：候选数据及来源、G1 问题卡。实际下载/访问须遵守项目的授权和数据条款；公开可见不自动等于可再分发或可上传其他服务。

产物：`DATA_REGISTER.md`、可复查的读取和质量报告、样本流图草稿、`EXPOSURE_LOG.md`、可行性决定。保留原始文件或合法访问标识、获取日期、版本、散列及转换路径，不修改原始副本。

按实际设计核实：

| 检查对象 | 应解决的问题 |
|---|---|
| 可用变量 | 暴露/结局/时间、混杂或预测因子是否真实存在；定义、单位、测量时点与编码是否一致 |
| 样本单位 | 行是个体、样本、访视还是技术重复；重复、配对、家系、中心或批次如何处理 |
| 信息量 | 独立样本数、事件数、组间分布与设计是否支撑目标；采用有依据的精度/功效/学习曲线或设计诊断，不设通用最小数字 |
| 数据质量 | 缺失原因、异常、选择机制、测量误差、批次与潜在混杂；清洗规则是否改变目标人群 |
| 数据来源关系 | 队列/样本/论文间是否重叠，训练验证是否来自同一来源；未知不能写成独立 |
| 可计算性 | 文件可读取、存储/内存/运行时、关键依赖和许可；用小规模真实路径试跑 |

尽早排除致命条件：关键变量缺失且无合理替代、样本单位误认、无法区分来源、设计不支持目标结论等。能修正时更新问题与计划；不能修正时转向或终止。不得以预期结果出现作为可行性通过条件。结果或数据接触后允许调整研究计划和筛选规则，但须记录触发信息、调整内容、方法学理由、受影响对象和探索/正式属性；不能把事后调整写成结果接触前已经固定的方案。

## G3：分析准备与方案基线

输入：G2 实际结果、数据接触记录、可执行的草案管线。输出带版本和日期的方案、变量字典、分析配置、测试运行、检查与解释标准。

必须明确：

- 主要问题、终点/目标量、分析集、纳排、变量变换和模型设定；主要、次要、探索分析的标记。
- 缺失处理、混杂/批次策略、分组/配对、模型假设及诊断、效应及不确定性表达、多重分析处理和敏感性分析。
- 预测研究按个体/中心/时间等真实依赖选择划分；插补、标准化、特征筛选和调参放在相应训练折内，验证集访问有记录。结果看过后不能继续称作未触碰的验证。
- 因果目标明确识别假设、时间顺序、偏倚与不可检验部分；数据相关不自动支持因果或机制结论。
- 技术试跑覆盖读取到结果输出，核实单位、对齐、样本数和边界情况；技术通过不能替代设计评审。
- 承诺哪些属于固定方案，哪些需要根据诊断调整，以及改变后如何标记偏离和影响。

已见结果必须如实登记。事后写出的“基线”只能用于约束后续工作，不能宣称事前预注册。是否登记、时间及平台按实际情况记录。

## 关口的决定方式

每个关口记录证据版本、评审者、结论、理由和待解决事项。选择 `pass`、`conditional`、`fail` 或 `pending`。允许有条件继续处理独立事项，但依赖未满足条件的正式工作不得冒充已放行。`conditional` 不满足脚本 `--require-gate` 的通过条件。

若用户或新证据要求改变主要问题、终点或验证设计，先展示可审查的影响和备选，再由约定责任人决定；一般的方案内实现调整直接执行。关口决定可以由负责人在会话中作出，并记录原意，无需另创签字流程。Methods 记录最终采用的设计；重要方案偏离、结果接触和探索性分析按项目及适用研究规范如实披露，不能用省略记录来制造事前确认性印象。

## 正式分析与结论挑战

正式运行记录数据、代码提交/散列、参数、环境及命令；记录起止状态、日志与输出。随机种子、软件版本和线程策略按需设置，按预先说明的容差复现，不承诺跨硬件逐字节一致。保留失败运行和排除原因，避免只留下成功结果。

主分析、方案偏离和探索结果分别报告。挑战结论时检查竞争解释、数据泄漏、选择偏倚、测量误差、模型稳定性和合理替代设定；从风险选择检查，不强制堆叠分析。解释效应与不确定性，报告负结果，不围绕显著性反复试探直到“通过”。

为每条重要结论建立链条：结论 ID → 当前结果/图表 → 统计输出 → 管线/参数 → 数据与来源。冲突证据保留并解释；无法解决时降低结论强度。

## 图表、正文与投稿前材料

先为每个图/表定义它支持的问题、读者需要比较的对象与对应结论，再选择表达。科学检查关注单位、样本、误差条定义、比较、选择与结论；技术检查关注数值、映射、导出和可读性；视觉检查关注图面、文字、颜色和布局。仅有脚本成功不代表图合格。

正文中的样本数、效应、不确定性和图表编号从已验收结果核对。引用逐项核实原文支持，避免以二手摘要代替关键证据。调用绘图、文档或检索技能时使用技能协作协议，不让专项技能自行改变研究问题。

投稿前交付清单按目标期刊当时的官方要求核实，至少考虑：正文、图表/图注/源文件、补充方法与结果、报告清单（若适用）、代码与环境说明、数据可用性和许可说明、利益冲突/伦理说明、作者贡献与作者待确认项、投稿信草稿。作者身份、同意、声明和伦理信息不由 AI 虚构。准备材料与实际提交分开处理，提交须有对应授权。

冻结本次交付版本，记录清单和残留问题。数据、分析或结论后来有改变时，按依赖使相关图、正文、摘要和投稿材料重新检查，不只替换某个文件。
