# 论证骨架与边做边写

> 作用：从立项第一天起维护论文的论证骨架，让每个结果、决定和来源产生时就进入写作素材，最后写论文时只需组装和打磨，不必重做。不负责：来源与论断的证据规则（见 [资料与证据](evidence-and-materials.md)）、投稿包（见 [固定交付](release.md)）。对应检查点 CP8–CP9。

## 1. 原则

- 论文是论证，不是工作日志。骨架回答三个问题：我们发现了什么，为什么可信，为什么重要。
- 骨架随证据走，证据不随骨架走。结果改变时修改故事，并记下修改原因；不为了维持故事而挑选结果，也不把事后形成的假设包装成事前假设（HARKing）。
- 写作素材在事件发生时产生：方法定了就写方法段，结果验收了就写结果段和图注草稿。到写作阶段，只剩组装、衔接和润色。

## 2. `manuscript/NARRATIVE.md`

研究项目初始化时生成这个文件，模板见 `assets/research/NARRATIVE.md`。包括：

1. 工作标题，和一句话结论（当前最佳表述，及其证据状态：设想 / 部分支持 / 已支持）。
2. 读者与意义：谁会在意，答案改变了什么。
3. 故事线：背景 → 空白 → 问题 → 方法 → 发现 1…n → 意义与局限。每个节点引用 `Q-*`、`H-*`、`CLAIM-*`。
4. 图故事板：每张主图回答什么问题、支撑哪条 CLAIM、包含哪些子图（panel），以及数据状态（计划 / 运行中 / 完成 / 已核验）。图在做分析之前就先“画”出来，没有图的分析要问一句是否值得做。
5. 缺口：要让故事成立还缺哪一环。它直接输入 [下一步导航](question-shaping.md)。
6. 预期审稿质疑与准备：每条写明质疑、现在的回应、还要补什么。
7. 目标期刊候选：定位、篇幅与图表限制，以及要求的核查日期。
8. 修订记录：版本、日期、变化原因（引用 `F-*` 或 `D-*`）。

## 3. 何时写什么

| 触发事件 | 立即写入 | 位置 |
|---|---|---|
| 证据地图完成（CP2） | 引言素材：背景、空白、最接近的工作及差异 | `manuscript/sections/introduction.md` 草稿 |
| 方法或设计定稿（`D-*`） | 方法段草稿，引用方案版本 | `manuscript/sections/methods.md` |
| 数据登记（`DATA-*`） | 数据来源、版本、纳排规则与可用性声明的素材 | 方法段；投稿包里的数据可用性说明 |
| 结果验收（artifact 状态变为 accepted） | 结果段草稿与图注草稿，标注 `CLAIM-*` 和数字来源 | `manuscript/sections/results.md` |
| 解释简报（CP6） | 讨论素材：解释、竞争解释、局限 | `manuscript/sections/discussion.md` |
| 负结果或偏离 | 局限段或补充材料素材；方案偏离披露 | 讨论或补充材料 |
| 模拟审稿 | 预期质疑与回应 | `NARRATIVE.md` 第 6 节 |

草稿中的每个数字都标注来源（例如 `[RUN-012: results/table2.csv]`），在投稿前对账时统一核对。章节文件按需建立，不预先生成空文件。需要成稿或改写时，调用 `scientific-writing` 技能；需要出图时，调用 `scientific-visualization`；需要核对引文时，调用 `citation-management`。

## 3a. 触发与留空登记

- **CP2（G1 之前）必须写入**：工作标题与一句话结论（可标“设想”）、读者与意义、故事线中的背景/空白/问题节点、预期审稿质疑（检索中发现的重叠研究、对照或独立性问题）。G1 之后骨架仍是空模板，`check_project.py` 会给出警告。
- **分析开工前先画图**：每个正式分析在意图简报里写明“对应哪张主图、支撑哪条 CLAIM”。答不出来就先问：这项分析值不值得做。正式统计若未在图故事板中登记，检查器给出警告。
- **允许留空的部分**：结果段、图注和讨论段只在结果验收后写。结果未被接受、方向暂停或终止时可以留空，但要在修订记录中写明原因（引用 `D-*`）。
- **主线暂停或终止时**：骨架冻结为当时版本，写明哪些论断成立、哪些不成立、哪些质疑没有解决。这些内容是转向时最有用的材料，不要清空。

## 4. 叙事锁定（CP8）

主要结果基本到位后，AI 准备以下材料：

- 当前骨架，以及它和上一版的差异；
- 每条主要 CLAIM 的强度和证据链（CLAIM → 图表 → 统计输出 → RUN → 数据或来源）；
- 缺口清单，每项写明补上它的代价，以及不补的后果（降低论断强度、移到补充材料、写成局限）；
- 模拟审稿意见：调用 `peer-review` 技能，由一个与写作者不同的上下文完成；它的意见只是待核实的提示，不算证据。

负责人决定锁定主线、补做、降低论断强度或改投方向，决定记为 `D-*`。锁定后如果主要结论改变，要开 `CH-*` 变更，并对摘要、标题、图和正文做影响追踪。

## 5. 投稿前（CP9）

1. 用检索日志做一次增量检索（只查上次检索之后的文献），确认没有被抢先，也没有遗漏新出现的反方证据。
2. 对账：正文中的每个数字、每条 CLAIM、每张图都对应已验收的结果版本，每条引用都经过核实。
3. 换一个新上下文做一轮模拟审稿；针对重大质疑，补做分析或调整措辞。
4. 按 [固定交付](release.md) 生成投稿包，作者信息、利益冲突声明、伦理声明由人确认。
