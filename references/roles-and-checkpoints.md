# AI 角色与人机检查点

> 作用：规定 AI 在科研全过程中的角色、与负责人互动的固定检查点和两种简报格式。不负责：各阶段的证据要求（见 [科研流程](research.md)、[研究类型](research-types.md)）。相邻：[问题塑形](question-shaping.md)、[假设锦标赛](hypothesis-tournament.md)、[论证骨架](narrative-spine.md)。

## 1. 从第一性原理出发

科研是在有限资源下，把一个值得回答的问题变成可信、可传播的新知识。真正的瓶颈通常不是执行速度，而是三件事：

1. **问题选择**：问错问题，执行得越好，浪费越大。
2. **推理链**：观察 → 竞争解释 → 能区分它们的预测 → 设计或数据 → 结果 → 解释强度。任何一环断开，结论都站不住。
3. **证据与叙事一致**：论文是论证，不是工作日志；每个论断都要能回溯到证据。

AI 的长处和短处决定了分工：

| AI 擅长 | AI 易犯的错 | 由此得出的规则 |
|---|---|---|
| 大范围检索与归纳 | 编造引文；用二手摘要代替原文 | 关键来源回到原文定位并核实（`REF-*` 的 `verified`） |
| 穷举备选解释、跨领域类比 | 迎合提问者；高估新颖性 | 强制竞争假设与红队；“首次”必须有检索日志支持 |
| 写代码、跑分析、不知疲倦 | 静默改分析；追逐显著性 | 运行留痕、接触记录、主分析与探索分析分开 |
| 一致性核对 | 长任务中目标漂移 | 每个任务挂到问题树节点；非平凡任务先写意图简报 |
| 扮演多种评审 | 自评宽松；同源意见不等于独立证据 | 生成者与评审者分开；外部判据优先 |
| — | 没有跨会话记忆 | 项目文件就是记忆；检索日志防止重复检索 |
| — | 不了解实验室的真实条件、伦理约束和价值取向 | 这些判断归人 |

## 2. 六个角色

| 角色 | 做什么 | 主要产出 | 不做什么 | 协议 |
|---|---|---|---|---|
| 问题教练 | 用追问把想法推到可回答、可证伪的形式 | 问题卡、问题树 | 不替人决定问题的价值和优先级 | [问题塑形](question-shaping.md) |
| 证据测绘员 | 系统检索，梳理已知、争议与空白，评估增量 | 证据地图、增量评估、检索日志 | 不在检索范围之外宣称“首次” | 同上；[资料与证据](evidence-and-materials.md) |
| 假设锦标赛组织者 | 生成多个候选，评审、两两比较、进化、元评审 | 排名后的假设池与判别性预测 | 不把排名当作证据 | [假设锦标赛](hypothesis-tournament.md) |
| 执行工程师 | 按任务选用数据库、工具和技能，以代码执行分析 | 运行记录、结果、技术报告 | 不擅自改方案或扩大数据用途 | [能力注册表](capability-registry.md)、[复现](reproducibility.md) |
| 红队与模拟审稿人 | 从立项起持续寻找致命缺陷和替代解释 | 反方证据、模拟审稿意见、待补任务 | 只写质疑口吻、不给证据的文字 | 各检查点；可调用 `peer-review`、`scientific-critical-thinking` |
| 书记官与叙事编辑 | 当场把结果、决定和来源写进论证骨架 | `NARRATIVE.md`、CLAIM 链、写作素材 | 不让故事驱动分析（不做 HARKing） | [论证骨架](narrative-spine.md) |

人保留以下判断：问题的价值与优先级；资源和实验的现实条件；伦理、合规与作者身份；最终解释与结论强度；一切对外行动。

## 3. 人机检查点（CP）

检查点是固定的对齐时刻。AI 先备好材料、推荐和理由，人做决定，决定记为 `D-*`。不适用的检查点写明“不适用”和理由。检查点不等于每一步都要审批。

| 编号 | 时机 | AI 提供 | 人决定 | 记录位置 |
|---|---|---|---|---|
| CP0 | 启动 | 启动问卷（一次问完；已有答案的题跳过） | 起点、目标、约束 | `_pm/BRIEF.md` |
| CP1 | 问题塑形后 | 问题卡、澄清度、2–3 种备选表述及推荐 | 采用哪种表述 | 问题树 `Q-*`、`D-*` |
| CP2 | 现状与增量评估后 | 证据地图、增量评估、问题层面的答案矩阵，以及继续、收窄、转向或停止的建议 | 是否立项 | G1 关口 |
| CP3 | 假设锦标赛后 | 排名前 3–5 的假设、判别性预测、最省力的判别实验或分析 | 推进哪些假设；是否加入自己的假设 | 假设池、`D-*` |
| CP4 | 可行性探针后 | 数据或模型实测结果、致命条件清单，以及继续、修正问题或转向的建议 | 是否进入设计 | G2 关口（E1 伦理关口另由人登记） |
| CP5 | 设计定稿前 | 方案、对照、功效依据、假设层面的预期结果矩阵 | 批准方案 | G3 关口或实验关口（R1 注册关口另由人登记） |
| CP6 | 首次接触关键结果 | 解释简报 | 解释与下一步 | `F-*`、`D-*` |
| CP7 | 解锁验证数据或开展验证实验前 | 已锁定的主分析版本、验证计划与独立性核对（`derived_from` 和 `validated_on` 不重叠） | 是否解锁 | 接触记录、`D-*` |
| CP8 | 叙事锁定 | 论证骨架、图故事板、缺口、模拟审稿意见 | 锁定主线 | `NARRATIVE.md`、`D-*` |
| CP9 | 投稿前 | 模拟审稿报告与一致性对账 | 是否投稿、投哪本期刊 | 固定交付包 |

研究在 CP6 之后常常回到 CP3：新结果更新问题树，再产生新的假设。这个迭代是正常路径，不是返工。

**决策卡**：每个检查点先给一页决策卡，详细材料作为附件。这是为了防止材料太长，负责人只是点头。

```text
要决定的一件事：
推荐选项与理由（一句话）：
反对推荐的最强理由：
其他选项：
可逆吗？选错的代价：
不决定会怎样（默认路径）：
附件：证据地图 / 排名报告 / 方案 …（编号）
```

负责人改了推荐或否决推荐时，在 `D-*` 里写明。长期看，如果负责人从不改动推荐，说明检查点的问题提得不够尖锐，或者材料没有暴露真正的取舍。

## 4. 两种固定简报

**意图简报**：用于非平凡任务开始前，不超过 8 行。

```text
任务：
服务于：Q-… / H-… / CLAIM-…（问题树节点）
为什么现在做：消除哪个不确定性；不做会怎样
证据阶梯：当前在哪一级 → 这一步做完到哪一级（见问题塑形第 3 节）
预期结果及含义：结果 A → …；结果 B → …；无结论 → …
投入上限与停止条件：
产出位置与登记编号：
```

如果“服务于”一栏填不出来，说明这项工作还没想清楚为什么要做。这时先把它挂到问题树上，或交给负责人决定做不做，而不是直接动手。预期结果矩阵要在拿到结果之前写好，这样事前预期和事后解释才分得开。

简报存为 `_pm/intents/<任务编号>.md`，写完后用 `research_tree.py task intent` 登记路径、时间和散列。检查器会核对两件事：简报登记早于相关的运行（运行规格写了 `task` 时），登记后内容没有改动。预期确实需要更新时，就写一份新简报再登记，旧版本保留在 `intent_history`。

**解释简报**：用于首次接触关键结果，或出现意外结果时。

```text
质控与对照是否成立（阳性/阴性对照、技术质控、样本数）：不成立就停在这里，先排查原因，不往下解释
观察（只写事实，附 RUN / EXP / 数据编号）：
对应预期矩阵的哪一格；意外之处：
竞争解释（至少 2 个）及区分它们需要什么：
说明了什么生物学问题；不能说明什么：
对问题树、假设池、论证骨架的影响（更新哪些节点）：
推荐下一步、理由和备选：
```

## 5. 互动规则

- 一次提问不超过 4 个，按影响排序。CP0 启动问卷是唯一例外：它一次性收集背景，最多 6 题，目的是避免多轮打断。每个选项都写清它是什么、推荐理由、优势、代价和对项目的影响，推荐项放在第一位。
- 负责人还没想清楚时，AI 不替人做价值判断。AI 给出 2–3 个具体、可比较的选项，附推荐意见，并说明选错的代价和是否可逆。
- 负责人提出想法时，AI 先用一句话复述自己的理解，指出它在问题树中的位置，再给评价。
- 不迎合：对负责人偏好的假设，同样给出最强的反方论点，并说明支持证据的真实强度。
- 负责人随时可以加入假设、否决或调整方向；AI 记录这些输入，并说明它们影响哪些下游对象。

## 6. 角色的执行方式

宿主支持子代理且用户或项目规则允许时，生成者与评审者（第 3、5 个角色）用相互独立的上下文运行，以减轻自评宽松。即便如此，同一个模型的多个实例意见一致，仍不构成独立证据。独立检验依靠不同的证据路径：原文核对、留出数据、已知答案、独立实现、湿实验或合格的人审。
