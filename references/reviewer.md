# 负责人审阅

审阅项要让负责人知道：需要决定什么、建议是什么、还有哪些方案、不决定或改变会怎样、依据在哪里、对应哪个版本。区分待处理、已评论、需补证据、有条件、接受、拒绝和过期。正式答复记录真实责任人、时间、原意与证据；有条件不等于接受，评论不等于批准。

六个视图由一套权威记录生成：项目概况、待审事项、成果与交付、任务与依赖、风险与变更、证据与历史。展示实际状态而非没有分母的完成百分比；成果接受、任务完成、科学可信程度和复现范围分别表达。页面有关键词筛选、稳定编号和本地证据链接，可离线打开或打印。

```text
python <skill>/scripts/render_review.py --project <project>
python <skill>/scripts/render_review.py --project <project> --check
```

输出到 `layout.review`（默认 `review/index.html`）和 `snapshot.json`。页面只读，没有会制造虚假授权的批准按钮。负责人可在真实对话或项目既定渠道答复，由执行者登记后重新检查与生成。

快照保存源文件指纹；`--check` 比较当前登记源记录和页面指纹，退出码非零表示需要处理。打开浏览器不会自动监听本地文件变化；更新台账、证据、代码或包后应主动检查。只对纳入指纹的本地文件生效，不声称核验未登记的远程资料。

需要“上次审阅后变化”时，将实际审阅对应的 `snapshot.json` 另存为 `_pm/reviews/<审阅ID>-snapshot.json`，登记真实审阅决策，再使用：

```text
python <skill>/scripts/render_review.py --project <project> --baseline _pm/reviews/R-001-snapshot.json
```

基线比较提供文件新增、缺失和内容变化线索，不等于对全部语义变化的理解，也不证明该基线曾被人审阅。未指定基线则明确提示；不能把上次生成页面时间当成上次负责人审阅时间。
