# 质量状态与检查

本页解释验收含义。字段与兼容规则只在[状态结构](state-schema-v2.md)维护，登记命令与变更闭环在[治理协议](governance.md)。

## 判断什么才算完成

| 状态 | 含义 |
|---|---|
| draft / produced | 草稿或已生成，尚不代表完成检查 |
| checked | 做过检查，检查结果可能含失败 |
| accepted | 当前版本满足约定的必要检查，且有明确接受依据 |
| stale / rejected | 依赖失效或拒收，不能冒充当前可用结果 |

按对象选择适用检查，不要求每项具备所有类别：

- `machine`：数值、结构、文件或程序行为，保存方法和可复查输出。
- `source`：原始出处及其支持范围，保存可定位证据。
- `professional`：方法、科学解释、图面或其他专业判断，保存问题、理由和真实评审者/角色。

检查为`pending/pass/fail/waived`。仅非必要检查可有具名、有理由的豁免；必要检查缺失、失败、版本不符不得验收。AI辅助检查须说明范围，不能写成真人审阅或独立实证；截图存在不证明视觉合格。

## 变更与检查器边界

输入、方法、代码、规则或关键解释改变时，先识别影响链，按治理协议登记需更新/无需改动的依据。保留有效上游，失效下游标记stale；停止/取消任务不因输入更新自动恢复。重跑或复审写新版本/检查，不改旧记录制造一直正确的印象。

`check_project.py`只读。退出码0表示在已登记范围未发现结构/文件不一致，不表示科学充分、审批真实或完整复现；记录未覆盖的对象不会自动检查。`--impact`列下游，`--require-gate`核指定关口，`--verify-hashes`核已有散列并报告未记录项，不宣称核遍远端数据。记录中的命令不会被执行。
