# 竞争解释与可选锦标赛

用于CP3选择优先核查的解释或路线。简表是可用的完整比较方式；仅当候选较多、选择代价高且进一步排序会改变资源分配时，才用锦标赛。起点问题尚不清楚时先回[问题塑形](question-shaping.md)。

## 1. 先确认比较对象

科学解释可共存，不要求互斥。设计无法识别因果是论断边界，代码是否正确是实现核查，先做哪项工作是任务优先级；它们不与生物解释混成真相排名。若比较任务，明确目标为信息价值与代价。

CP3材料说明候选解释、判别性预测、支持/反证、最普通的替代解释及最小核查；已有明确研究方案时核其选择依据即可。负责人选择后登记D及被放弃/保留的备选；简表足够时注明无需锦标赛的理由，不以候选数为硬门槛。

## 2. 锦标赛的记录

只有选择锦标赛才建立`_pm/research/tournaments/<TID>/`：

| 文件 | 作用 |
|---|---|
| config.json | 问题/目标、标准与权重、约束、预算、Elo参数和冻结状态 |
| hypotheses.jsonl | 假设、机制或解释、预测、来源/策略/父条目与状态 |
| reviews.jsonl / matches.jsonl | 具名/具角色的评阅、顺序、比较理由与结果 |
| META_REVIEW.md | 反复缺陷及下轮要求 |
| ranking.json / REPORT.md | 可从比较记录重建的排序、比较次数及限制 |

追加记录而不改写过去；进化假设用新条目和parents。来源与论文论断回一手证据核实；外部系统的借鉴记录见[设计经验](design-lessons.md)，不是本轮必读。

## 3. 已选锦标赛时的流程

1. 按原授权确认比较目标、标准、约束和预算后freeze；规则变更记录决定及既有比较影响。
2. 生成可区分的解释，保留`null`普通解释；负责人的条目以human来源与其他候选同等比较。多策略/多代理只在实际授权和收益允许时使用。
3. 按风险做事实/可检验性初审、原始来源与新颖性核查、子论断验证和失败场景推演；不为每个候选机械执行相同多轮。已有可靠文献核查可引用，未知不判新颖。
4. 按冻结标准比较，记录理由而非文采偏好；为关键对阵做反序检查以暴露位置影响。用`blind --order`逐场材料，反序评阅不先读正序评语、全轮packet或排名；无法隔离就如实标记非独立。
5. 需要时追加改进条目与元评审；预算到限、排序不再提供决策信息或负责人叫停则结束，不为了填满场数继续。
6. 负责人据证据、风险和代价选择，不强制对固定数量候选盲评。可实际收集人评并报告一致性；没有就注明未进行，不伪造human记录。

Elo只表示本轮评委对优先检验的相对偏好，不是支持某解释的实证。报告各候选场数、顺序暴露与不稳定性；null排前列不能静默删掉。移出null须有已采纳决定。

## 4. 工具入口

先登记问题，再用`tournament.py init/freeze/add/review/blind/match/status/rank/promote`，完整参数看`--help`。例如：

```text
python <skill>/scripts/tournament.py --project <project> blind --id T01 --a T01-H001 --b T01-H004 --order ba
```

`promote`只把候选登记为项目H，要求已采纳CP3决定并保留排名来源；后续状态由research_tree维护。脚本只记录/计算，不调用模型或证明评委判断正确。
