# 问题塑形、现状与科学增量

> 作用：把初步想法推到可回答、可证伪、值得做的研究问题，评估现状与科学增量，维护问题树并导航下一步。不负责：假设的生成与排名（见 [假设锦标赛](hypothesis-tournament.md)）、数据和设计细节（见 [科研流程](research.md)、[研究类型](research-types.md)）。对应检查点 CP0–CP2，见 [角色与检查点](roles-and-checkpoints.md)。

## 1. 启动问卷（CP0）

先读已有材料，已经有答案的题目跳过。剩下的题目一次问完，最多 6 题：

1. 这个问题从哪里来：一个观察、一篇文献、一个临床难题、一批手头数据，还是一项技术？
2. 你已经知道什么、做过什么：读过的关键文献、预实验、已有数据、失败的尝试。
3. 你最想要的结果是什么：理解机制、找到靶点或标志物、改变实践、建立方法、毕业或基金？
4. 有哪些资源和限制：数据、样本、实验平台、动物或伦理许可、经费、时间、合作方。
5. 什么结果算成功，什么结果会让你放弃？
6. 你倾向的假设是什么？（记为 `origin: human`。在锦标赛里它和 AI 生成的假设同等竞争。）

## 2. 澄清度阶梯

| 级别 | 形式 | 例子（示意） | 还缺什么 |
|---|---|---|---|
| L0 主题 | 领域或兴趣 | 铁死亡与肝癌 | 现象 |
| L1 现象 | 观察到或怀疑的现象与空白 | 铁死亡可能参与 HCC 对索拉非尼的耐药 | 系统、比较、读出 |
| L2 可回答的问题 | 研究单位、系统、比较、读出、时间关系都已指定 | 在耐药 HCC 细胞系与患者队列中，耐药是否伴随铁死亡抵抗？ | 机制和预测 |
| L3 可检验的假设 | 有机制，且有能区分备选解释的预测 | X 通过 Y 抑制脂质过氧化，介导耐药；若敲低 X，预期出现 … | 测量与设计 |
| L4 可操作 | 测量、设计、对照、数据和样本量都有着落 | 读出方式、对照、功效依据与数据来源 | 决策准备 |
| L5 决策就绪 | 有答案矩阵、杀死条件和投入上限 | 见第 5 节 | — |

进入 CP1 至少要达到 L2；进入设计（CP5）至少要达到 L4。不要跳过级别。从 L0 直接跳到选算法或做实验，是“做了很多却说明不了问题”的常见原因。

## 3. 追问清单

按缺口选用，不必全问：

- **层次与单位**：现象发生在哪个层次（分子、细胞、组织、个体、人群）？分析单位是什么？技术重复和生物学重复分别是什么？
- **比较**：和什么比？对照能排除哪些解释？
- **问题类型与论断强度**：问题是描述、关联、预测、因果还是机制？你需要多强的论断，数据和设计能支撑到哪一级？
- **机制证据阶梯**（生物医学适用）：相关 → 必要性（敲低、敲除、抑制）→ 充分性（过表达、激活）→ 直接性与通路位置（直接结合或修饰；上位关系与回补实验确定上下游）→ 生理相关性（体内、人体样本）→ 可转化性。特异性不是单独的一级，而是每一级结论成立的前提：要用回补、多种独立干预手段（不同 siRNA、敲除、抑制剂）和合适的对照排除脱靶效应。写明本研究打算到达哪一级、凭什么到达。
- **操作定义**：核心表型要写成可检测的判据，而不只是一个名词。例如“铁死亡”要同时满足：脂质过氧化升高（C11-BODIPY 或 MDA）；能被铁死亡抑制剂（Ferrostatin-1、Liproxstatin-1）或铁螯合剂（DFO）逆转；凋亡抑制剂（如 Z-VAD-FMK）和坏死性凋亡抑制剂不能逆转。参照领域共识或指南来设定判据。
- **最无聊的解释**：结果能不能被混杂、批次、细胞组成差异、反向因果、选择偏倚、测量伪影或脱靶效应解释？
- **答案的用处**：答案是 A 和答案是 B 时，你接下来的行动有什么不同？如果没有不同，这个问题对决策没有价值。
- **杀死条件**：发现什么证据，你会放弃或改问题？
- **为什么是现在、为什么是你**：有没有新数据、新技术、独特样本，或者别人都没注意到的观察？

临床或人群问题，用 PICO/PECO（人群、干预或暴露、对照、结局）补全，并写明时间零点和随访窗口。实验问题，用“系统 × 扰动 × 读出 × 对照”补全。组学问题，先写出生物学问题，再看数据；不接受“看看数据能告诉我们什么”作为问题本身。数据驱动的探索可以做，但要标为探索性，它的输出是新的问题或假设，不是结论。

## 4. 证据地图与现状

在第一轮系统检索之后，产出证据地图：

| 类别 | 内容 |
|---|---|
| 已确立 | 结论、证据类型与强度、核心 `REF-*` |
| 有争议 | 互相矛盾的结果，以及可能的原因（模型、剂量、人群、方法） |
| 空白 | 没人做过，或做得不充分的部分；注明检索范围和日期 |
| 最接近的工作 | 3–10 篇：做了什么、没做什么、局限在哪；本研究与它们差在哪一步 |
| 竞争态势 | 近两年的预印本、注册中的试验、活跃的课题组 |

完整的证据地图写在 `references/EVIDENCE_MAP.md`（每个根问题一节，注明依据的 `S-*` 范围和更新日期）。研究方案只引用其摘要，不复制。所有检索都记入 `references/SEARCH_LOG.md`，见 [资料与证据](evidence-and-materials.md)。只有检索日志能证明检索范围时，才可以写“未见报道”；不能写“首次”，除非你有充分把握，并在正文中如实说明检索范围。

## 5. 科学增量评估（CP2）

先判断增量属于哪种类型：新现象；机制上升一级；新情境或推广（人群、组织、物种、时间）；解决矛盾；新方法或新资源；有意义的阴性结果；稳健性或重复验证；转化或临床应用。“换个疾病名”“换个算法”“多画几张图”本身都不构成增量。

逐项评估，每项给 1–5 分。分数只是摘要，必须写明理由和依据，因为有理由的分数才能被复核：

| 维度 | 要回答的问题 |
|---|---|
| 重要性 | 答案会改变谁的理解、实践或方法？改变有多大？ |
| 新颖性 | 相对于检索日志，属于哪种增量？最接近的工作差在哪里？ |
| 可回答性 | 设计和数据能把论断支撑到需要的强度吗？ |
| 可行性 | 数据、样本、平台、技能、时间和经费是否到位？关键瓶颈在哪？ |
| 风险结构 | 结果为阴性时还有价值吗？优先选结果无论正负都有信息量的问题 |
| 时机 | 是不是热点？会不会被抢先？有没有窗口期？ |

**问题层面的答案矩阵**（CP2；此时还没有排出假设，所以只针对问题本身的答案）：

| 问题的答案 | 含义 | 能支撑的论断 | 下一步 | 是否可发表或有用 |
|---|---|---|---|---|
| 是 | | | | |
| 否（检验效能足够） | | | | |
| 部分 / 依条件而定 | | | | |
| 无结论或技术失败 | | | | |

在 CP3 选定假设之后，再在 CP5 设计定稿时，写假设层面的预期结果矩阵（支持主假设、支持竞争假设、无效应、无结论），并写进意图简报。

把结论分成继续、收窄、转向、停止四种，给出推荐和理由，再交给负责人在 CP2 决定，记为 G1 关口和 `D-*`。需要压力测试时，可调用 `what-if-oracle`；需要提升问题高度时，可调用 `ambitious-ai`。

## 6. 问题树与下一步导航

问题树：根问题（Q）→ 子问题（Q）→ 假设（H）→ 判别性预测 → 任务、分析或实验 → 结果与发现（F）→ 论断（CLAIM）。

分工：`project-state.json` 的 `questions` 和 `hypotheses` 是当前表述、澄清度、预测、状态和链接的唯一权威来源；`_pm/research/HYPOTHESES.md` 只写论证（为什么这样问、机制推理、证据摘要），用编号引用状态，不重复抄写状态。用 `research_tree.py` 写入：

```text
python <skill>/scripts/research_tree.py --project <project> question add --id Q-001 --statement "…" --clarity 2
python <skill>/scripts/research_tree.py --project <project> question set --id Q-002 --parent Q-001 --type wet_lab
python <skill>/scripts/research_tree.py --project <project> hypothesis add --id H-001 --question Q-002 --statement "…" --prediction "…" --origin human
python <skill>/scripts/research_tree.py --project <project> task link --id T-003 --serves H-001
python <skill>/scripts/research_tree.py --project <project> task intent --id T-003 --path _pm/intents/T-003.md
```

每条命令都先在副本上运行检查器，只有不引入新错误时才写入（例如父问题不存在、问题树出现环、已检验的假设没有发现作为证据，这些都会被拒绝）。任务用 `serves` 挂到节点上；研究项目一旦有了问题，检查器会提示还没有挂靠的任务。

负责人不确定下一步做什么时，AI 按下面四点给出排序后的 2–3 个选项：

1. 哪个不确定性一旦消除，最能改变后续决定或结论强度？这叫信息价值。
2. 消除它要花多少代价，失败了能不能及时止损？
3. 它依赖或阻塞了哪些节点？
4. 它是否通向论证骨架上缺失的那一环（见 [论证骨架](narrative-spine.md)）？

每个选项都附意图简报，说明它服务于哪个节点、预期结果及其含义、代价，以及为什么现在做。推荐信息价值除以代价最高的那一项。

## 7. 可调用的专项技能

先确认技能实际可用，再调用；参见 [技能协作](skill-composition.md)。

- 发散构思：`scientific-brainstorming`
- 假设表述与判别性预测：`hypothesis-generation`
- 证据质量评估：`scientific-critical-thinking`
- 文献检索与元数据核实：`citation-management`
- 情景压力测试：`what-if-oracle`
- 拉高目标：`ambitious-ai`
- 方法：`experimental-design`、`statistical-power`

专项技能的产物返回后，由主会话编号、去重并写入正式记录。
