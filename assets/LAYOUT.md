# 目录职责：{{PROJECT_NAME}}

具体角色到路径的权威映射在 `project-state.json` 的 layout。下列为默认职责，修改映射后核对本页和根入口；不自动搬迁旧文件。

| 默认路径 | 放什么 | 何时建立 |
|---|---|---|
| `_pm/` | 范围、方案、决策理由、发现、状态索引、评审证据 | 启动 |
| `references/` | 文献来源索引、外部资料、数据字典 | 首次使用 |
| `data/raw/` | 保留原貌的数据；无法内置时用登记表定位 | 实际获取 |
| `data/interim/` | 清洗转换中间产物 | 首次生成 |
| `data/processed/` | 有版本的分析输入 | 首次生成 |
| `src/` | 可运行、可复用代码 | 首次编码 |
| `notebooks/` | 探索过程；正式结果须有完整执行路径 | 需要时 |
| `runs/` | 重要运行的实际输入、参数、环境、日志、输出 | 正式运行 |
| `results/` | 统计结果、图表及来源索引 | 首次生成 |
| `manuscript/` | 正文、图注、补充和投稿材料的工作源文件 | 写作时 |
| `releases/` | 固定交付包；上传文件与内部检查分开 | 打包时 |
| `review/` | 自动生成的只读审阅快照 | 需要审阅时 |
| `archive/` | 退出使用的材料快照、原位置、原因及替代关系 | 实际退出时 |

文件按内容归属；通过验收时更新状态，不在“待审/通过”目录间反复搬动。子目录存在理解门槛时才加 README。大型数据不重复复制；临时文件按实际工具惯例管理。

README 面向人，AI_CONTRACT 面向执行，STATUS 负责上下文，state 负责状态索引，具体方案/发现/决策负责内容与理由。不要把同一事实手工维护成多份。
