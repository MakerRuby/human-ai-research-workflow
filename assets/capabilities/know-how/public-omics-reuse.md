# 公开组学数据复用

## 推荐流程

1. 先写出生物学问题和需要的变量（暴露、结局、协变量、时间），再去找数据，不要倒过来做。
2. 先按 [公共数据可行性](../../../references/public-data-feasibility.md) 核独立供体/有效配对上限和目标精度，再按需读取少量数据；细胞数、技术列和文章多组学总人数不代表每种测量的独立样本数。配对完整案例按每个目标分别列出。
3. 核对来源关系：同一批患者或样本是否出现在多个 GSE 或研究中；发现集与验证集是否来自同一中心或同一批次。未知时，不能写成“独立验证”。
4. 登记 `DATA-*`（版本、许可、访问日期、哈希），首次接触结果时写入接触记录。
5. 跨数据集整合时，先在每个数据集内分别分析，再做 meta 分析或谨慎地合并；记录批次校正的方式。
6. 验证资源元数据尽早核查；目标读出/效应在主分析及验证规则锁定后解锁。结构或QC读取是否可能暴露目标信号须事先说明，访问时间和范围写入记录。

## 当 RNA 集合相关突出时

以下只在解释依赖集合评分或跨测量共变时触发，不作为所有组学项目的额外分析清单。先按真正要排除的竞争解释设计有限审计，写清哪些结果会让候选退出。

- **测量含义**：外部通路或蛋白成员映射到RNA后，记录注释版本、歧义与成员损失；集合分数首先是RNA汇总。名称、富集或跨细胞相关不证明功能活化、配体特异响应、细胞互作或疾病特异性。集合内部一致性也需按实际证据描述。
- **可比的背景**：比较相关强弱时，考虑集合大小、两种测量中的表达均值/方差、检测率及成员重叠。共享同一成员的跨细胞分数应与相同成员结构的背景比较，不能只拿不同集合的低相关作参照。说明匹配规则及代价，不选择最有利的背景。
- **机械共享与稳定性**：必要时预定去重叠、拆成不重叠成员、去高影响成员、患者影响、深度/检测率或其他相关技术挑战。拆分集合的多次结果不是新增患者；其分位数不是患者效应的置信区间。
- **解释边界**：随机背景尾部比例在未定义有效零假设、抽样机制和选择处理前只是诊断，不能直接称校准P值。原队列bootstrap、留一分析和独立数值实现不消除候选的事后选择，也不替代新患者确认。观察到共享IFN等信号不自动建立某一种细胞因子特异性。

原主结果、探索候选、审计规则冻结时间和新验证状态分别保留。公平挑战通过后，仍须重新核对最接近工作及证据链；不以更大相关系数直接替换原主要终点。

## 该做与不该做

- 该做：报告纳入和排除的数据集及原因（含被排除的）；保存原始样本表；看效应方向是否一致，而不只看显著性。
- 不该做：在多个数据集里挑“结果显著”的那一个作为验证；用发现集的结果去选择验证集；把整合后的同源数据当作外部验证。

## 常见坑与对策

| 坑 | 症状 | 对策 |
|---|---|---|
| 元数据不全或混乱 | 分组只能从样本标题推断 | 回到原始论文核对；无法确认的样本排除并报告 |
| 同源重复 | 两个 GSE 的样本相关性异常高 | 用表达谱相关性或 ID 交叉核对，去重 |
| 选择性验证 | 只报告验证成功的数据集 | 事先规定验证集，全部结果都报告 |
| 平台差异 | 芯片与测序结果直接合并 | 分别分析，或使用适合跨平台的方法 |
| 生存分析的乐观偏倚 | 用同一数据挑选最佳截断值后直接检验 | 预先设定截断值，或在独立数据中验证 |

## 工具选择

| 情况 | 推荐 | 理由 |
|---|---|---|
| 找数据 | GEO / ArrayExpress / CELLxGENE / GDC 检索，结果登记到 SEARCH_LOG | 检索范围可追溯 |
| 下载与解析 | GEOquery / pysradb / GDC API | 有版本可循 |
| 跨数据集综合 | 随机效应 meta 分析 | 保留数据集之间的异质性 |

## 验证清单

- [ ] 每个数据集的样本数、分组与原文一致
- [ ] 发现集与验证集的来源关系已核实并记录
- [ ] 验证元数据与目标效应接触分开，效应解锁在分析规则锁定之后
- [ ] 结论措辞与研究类型相符（关联研究不写成因果）

## 排错

| 报错或异常 | 可能原因 | 处理 |
|---|---|---|
| 不同数据集的效应方向相反 | 人群、平台、定义不同，或其中一个结果是假阳性 | 查定义和处理流程差异，在结果中如实报告异质性 |
| 下载的数据与论文描述不符 | 数据集版本更新或存在勘误 | 记录版本，联系作者或换用其他数据 |
