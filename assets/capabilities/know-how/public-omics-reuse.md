# 公开组学数据复用

## 推荐流程

1. 先写出生物学问题和需要的变量（暴露、结局、协变量、时间），再去找数据，不要倒过来做。
2. 对候选数据集，实际下载样本表和一小部分数据，核对：样本单位、分组定义、平台、处理流程，以及临床变量是否真实存在。
3. 核对来源关系：同一批患者或样本是否出现在多个 GSE 或研究中；发现集与验证集是否来自同一中心或同一批次。未知时，不能写成“独立验证”。
4. 登记 `DATA-*`（版本、许可、访问日期、哈希），首次接触结果时写入接触记录。
5. 跨数据集整合时，先在每个数据集内分别分析，再做 meta 分析或谨慎地合并；记录批次校正的方式。
6. 验证集只在主分析锁定后访问，访问时间写入记录。

## 该做与不该做

- 该做：报告纳入和排除的数据集及原因（含被排除的）；保存原始样本表；看效应方向是否一致，而不只看显著性。
- 不该做：在多个数据集里挑“结果显著”的那一个作为验证；用发现集的结果去选择验证集；把整合后的同源数据当作外部验证。

## 常见坑与对策

| 坑 | 症状 | 对策 |
|---|---|---|
| 元数据不全或混乱 | 分组只能从样本标题推断 | 回到原始论文核对；无法确认的样本排除并报告 |
| 同源重复 | 两个 GSE 的样本相关性异常高 | 用表达谱相关性或 ID 交叉核对，去重 |
| 选择性验证 | 只报告验证成功的数据集 | 事先规定验证集，全部结果都报告 |
| 平台差异 | 芯片与测序结果直接合并 | 分别分析，或使用适合跨平台的方法 |
| 生存分析的乐观偏倚 | 用同一数据挑选最佳截断值后直接检验 | 预先设定截断值，或在独立数据中验证 |

## 工具选择

| 情况 | 推荐 | 理由 |
|---|---|---|
| 找数据 | GEO / ArrayExpress / CELLxGENE / GDC 检索，结果登记到 SEARCH_LOG | 检索范围可追溯 |
| 下载与解析 | GEOquery / pysradb / GDC API | 有版本可循 |
| 跨数据集综合 | 随机效应 meta 分析 | 保留数据集之间的异质性 |

## 验证清单

- [ ] 每个数据集的样本数、分组与原文一致
- [ ] 发现集与验证集的来源关系已核实并记录
- [ ] 验证集访问在主分析锁定之后
- [ ] 结论措辞与研究类型相符（关联研究不写成因果）

## 排错

| 报错或异常 | 可能原因 | 处理 |
|---|---|---|
| 不同数据集的效应方向相反 | 人群、平台、定义不同，或其中一个结果是假阳性 | 查定义和处理流程差异，在结果中如实报告异质性 |
| 下载的数据与论文描述不符 | 数据集版本更新或存在勘误 | 记录版本，联系作者或换用其他数据 |
